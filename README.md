# 🦊 Foxora

ربات مدیریت و ضد-هرزنامهٔ **سروش پلاس** — نسخهٔ مستقل ساخته‌شده از روی کد
واقعی و فعلی ربات **B2** (`splusesupor-oss/soroush-plus-antispam-bot-v2`)،
همراه با قابلیت‌های حفظ‌شدهٔ لاگ/CPU/صفِ نسخهٔ قبلی Foxora.

## ویژگی‌های کلیدی

- ضد-اسپم لایه‌ای (لینک، شماره، یوزرنیم، کلمات ممنوعه، فوروارد، GIF و رسانه)
- لیست کلمات ممنوعه با «کلمات بازنشسته» (`config/banned_words_retired.txt`) هم‌گام است: یک حرف تنها هرگز فیلتر نمی‌شود
- مدیریت کامل گروه: سکوت/بن/اخطار، قوانین، وایت‌لیست، انقضای گروه
- اقتصاد داخلی (سکه، فروشگاه، رتبه‌بندی) و بانک سرگرمی/بازی‌ها
- Watchdog با ری‌استارت خودکار و گزارش خصوصی به مالک
- معماری صف کران‌دار و منصفانه برای درخواست‌ها + governor اتصال مشترک
- لاگ غیرمسدودکننده با چرخش خودکار و سرکوب خطوط پرتکرار

## مسیر اجرا و جدایی از B2

| مورد | Foxora | B2 (دست‌نخورده) |
|---|---|---|
| دایرکتوری پروژه | `~/Foxora` | مسیر clone خودش |
| دادهٔ اجرایی (session/DB/config/log/backup) | `~/.foxora` | `~/.local/share/soroush-bot-bot2` |
| فایل اجرای اصلی | `foxora.py` | `bot2.py` |
| دستور اجرا | `./foxora` | `b2` |
| نشانگر instance | `.bot_instance` = `foxora` | `bot2` |
| متغیر session | `SOROUSH_SESSION_STRING_FOXORA` | `SOROUSH_SESSION_STRING_BOT2` |

Foxora هیچ فایل، session یا دیتابیسی از B2 را نمی‌خواند و نمی‌نویسد؛ قفل PID
هر instance جداست و دو ربات می‌توانند هم‌زمان روی یک دستگاه کار کنند.

## نصب (Termux)

```bash
git clone https://github.com/tbom8670-afk/Foxora.ai.git ~/Foxora
cd ~/Foxora
pip install -r requirements.txt
cp .env.example .env   # سپس session را داخل .env پر کنید
```

### اجرا

```bash
cd ~/Foxora
./foxora           # اجرا با Watchdog (پیشنهادی؛ ری‌استارت خودکار)
./foxora direct    # اجرای مستقیم بدون Watchdog
./foxora status    # وضعیت
./foxora stop      # توقف فقط Foxora
```

اولین اجرا برای ساخت session از شما ورود تعاملی می‌خواهد؛ session فقط در
حافظه نگه داشته می‌شود (StringSession) و فایلی روی دیسک نوشته نمی‌شود.

### مالک

مالک در `config/owner.json` (canonical) تعریف می‌شود و در اولین اجرا به
`~/.foxora/config/owner.json` هم‌گام می‌شود.

## ⚖️ دادگاه روباه (بازی جدید)

بازی گروهی ۵ نفره با قاضی هوش مصنوعی: `دادگاه` → ثبت‌نام با `شرکت` →
تخصیص تصادفی نقش‌ها (شاکی، متهم، شاهد شاکی، شاهد متهم، وکیل) → انتخاب جرم →
شکایت → دفاع → دو شهادت → دفاعیهٔ وکیل → رأی هوش مصنوعی → ۱۳ سکه برنز
(تبرئه) یا ۲۰ سکه برنز (محکومیت) + مجازات ۶۰ ثانیه‌ای حذف پیام متهم.

* ثبت‌نام پیوسته است: هر `شرکت` یک ثبت‌نام، شمارنده فقط بالا می‌رود و بعد از
  ری‌استارت ربات هم از همان فهرست ادامه پیدا می‌کند (بدون ریست).
* بازی برای **همهٔ اعضای گروه** است: `شرکت` در فهرست دستورهای بازی
  (`group_dispatch`) و پاسخ بازیکنانِ بازیِ در جریان از فیلتر هرزنگاری
  مستثناست؛ پیش‌تر این واژه در خط عادی بود و پیام اعضای عادی حذف می‌شد.
* همهٔ پیام‌های دادگاه **Bold** و ردیفی‌اند؛ هیچ نقل‌قولی استفاده نمی‌شود.

* دادهٔ بازی داخل خود پروژه: `data/court_game/{cases,sessions,ai_logs,results,config}`
* اقتصاد و مجازات از سیستم موجود ربات استفاده می‌کنند (بدون کیف پول/صف جدید)
* قاضی: Cloudflare Workers AI با مدل `@cf/meta/llama-3.3-70b-instruct-fp8-fast`
  (کلیدها فقط در `.env`؛ هیچ کلیدی در کد نیست)
* **پرونده هیچ‌وقت بی‌رأی نمی‌ماند:** اگر سرویس خطا بدهد یا سهمیهٔ روزانهٔ
  Workers AI تمام شود، «قاضی داخلی» با تحلیل محتوایی پرونده رأی می‌دهد و
  جایزه پرداخت می‌شود (جزئیات در `docs/COURT_GAME.md`)
* مستندات کامل: [`docs/COURT_GAME.md`](docs/COURT_GAME.md)
* تست: `python3 tests/test_court_game.py` و `python3 tests/test_court_join_all_users.py`

## قابلیت‌های حفظ‌شده از Foxora قبلی

قبل از جایگزینی با کد B2، قابلیت‌های زیر شناسایی و **حفظ** شدند:

1. **بهینه‌سازی لاگ و CPU** — لاگ غیرمسدود با صف کران‌دار و drop-on-saturation،
   سرکوب لاگ‌های پرتکرار پیام‌محور (`BOT_VERBOSE_LOGS`)، چرخش خودکار
   (`BOT_LOG_MAX_BYTES/BOT_LOG_BACKUPS`).
2. **صف درخواست‌های گروه‌ها** — `SerialRpcQueue` (یک RPC در هر لحظه، fairness
   بین گروه‌ها، bounded، dedupe فقط با کلید صریح)، `FairModerationQueue`،
   `FairDeleteQueue` و knob pacing `RPC_MIN_INTERVAL_SECONDS` که روی مسیر
   زندهٔ `RpcGovernor` هم اعمال می‌شود.

نگاشت کامل: [`docs/FOXORA_PRESERVED_FEATURES.md`](docs/FOXORA_PRESERVED_FEATURES.md)

## 🔒 عضویت اجباری کانال (Force Join)

هر گروه می‌تواند یک کانال اجباری داشته باشد: تا کاربر عضو آن کانال نشود،
پیامش در گروه حذف می‌شود. قابلیت عمداً «کم‌مصرف» طراحی شده است — مسیر هر
پیام **صفر فراخوانی API** دارد (کش حافظه → SQLite → حداکثر یک بررسی وقتی
وضعیت کهنه است).

> ⚠️ **واقعیت مهم سرور سروش:** `channels.getParticipant` روی سروش پیاده
> نشده است (`422 NOT_SUPPORTED`). پس بررسی عضویت **چندمسیره** است و اولین
> مسیری که جواب بدهد استفاده می‌شود:
> `getParticipant` → **Bot API `getChatMember`** (روش ربات‌های تلگرامی) →
> جست‌وجوی هدفمند عضو → **پیمایش هدفمند اعضا** (حکم قطعی برای همان کاربر) →
> اسنپ‌شات کامل اعضا. اگر هیچ مسیری جواب نداد،
> عضویت اجباری فعال **نمی‌شود** (پیام کسی بی‌دلیل حذف نمی‌شود).

- دستورها (فقط مالک گروه/مالک ربات؛ «وضعیت کانال» برای همه):
  `کانال من <لینک یا آیدی>` ، `حذف کانال من` ، `وضعیت کانال` ،
  `تنظیم عضویت اجباری` ، `لغو عضویت اجباری` ،
  `تست عضویت` (با ریپلای: «عضو هست» یا «عضو نیست»)،
  `تشخیص عضویت` (گزارش کامل فنی)، `راهنمای کانال`، `راهنمای اجرا`
- هنگام ثبت، ربات واقعاً **هر مسیر** را یک‌بار می‌سنجد
  (`getParticipant`، `getChatMember`، خواندنی بودن فهرست اعضا، ادمین بودن از
  فهرست ادمین‌ها، `can_view_participants` / `participants_hidden`) و نتیجه
  را ذخیره می‌کند تا مسیر مرده دوباره صدا زده نشود. اگر هیچ مسیری نباشد،
  قابلیت **فعال نمی‌شود** و دلیلش به مالک گفته می‌شود.
- در قطعی/تایم‌اوت API هیچ پیامی حذف نمی‌شود (fail-open) و «عضو نیست» از
  «دسترسی نداریم» تفکیک می‌شود.
- خروج از کانال با رویداد `UpdateChannelParticipant` فوراً باطل می‌شود؛
  اسنپ‌شات دوره‌ای + diff محلی، خروج‌های بی‌رویداد را می‌گیرد (اسنپ‌شات
  ناقص هرگز کسی را «خارج‌شده» ثبت نمی‌کند).
- **به‌محض ورود کاربر به گروه**، اگر عضویت کانال تأیید نشود همان لحظه لینک
  کانال برایش ارسال می‌شود (`FORCE_JOIN_NOTICE_ON_JOIN`)، و به‌محض اینکه
  عضو کانال شد پیام «✅ عضویت شما تأیید شد» می‌آید — حتی اگر حساب ربات
  ادمین کانال نباشد (صف تأیید، بدون نیاز به رویداد سرور).
- معاف: مالک ربات، مالک گروه، ادمین ثبت‌شده، ادمین واقعی گروه، VIP، ربات‌ها
  و پست‌های کانالی.

مستندات کامل (گزارش فنی سورس‌محور، معماری، اعداد بنچمارک و محدودیت‌های
صادقانه): [`docs/FORCE_JOIN.md`](docs/FORCE_JOIN.md)

```bash
python3 -m pytest tests/test_force_join.py -q    # ۸۳ تست
python3 tools/bench_force_join.py --messages 1000

# سنجش زنده: با این حساب کدام روش بررسی عضویت روی سروش جواب می‌دهد؟
# (ربات باید خاموش باشد؛ ابزار فقط می‌خواند)
./foxora stop
python3 -m tools.soroush_membership_probe --channel @mychannel
./foxora
```

## ⏳ پاک‌سازی خودکار پیام «اعلام مهلت گروه»

پیام تأیید مهلت (`تاریخ انقضای گروه تنظیم شد …`) با شناسه‌اش در رکورد همان
گروه ذخیره می‌شود و:

* با TTL برابر «زمان باقی‌مانده تا انقضا» به موتور `notice_cleanup` سپرده
  می‌شود (حتی اگر پروسه ری‌استارت شود، از فایل بازیابی می‌شود)؛
* در لحظهٔ انقضا صریحاً به صف حذف می‌رود (`EXPIRY NOTICE CLEARED`)؛
* با تعیین مهلت تازه، پیام مهلت قبلی همان لحظه پاک می‌شود.

بدون نیاز به هیچ دخالت مدیر. کلید رکورد انقضا نرمال‌شده (مثبت) است، اما
ارسال/حذف همیشه با شکل واقعی گروه (`-100…`) انجام می‌شود — قبلاً شکل مثبت
استفاده می‌شد که در سروش یعنی «کاربر خصوصی».

## 🖇 تشخیص لینک در بیوگرافی کاربران

کاربری که بیوگرافی‌اش لینک دارد با همان سیستم اخطار/حذف/سکوت یا اخراج فعلی
ربات مدیریت می‌شود. **بیوی هر کاربری که در گروه پیام می‌دهد، همان لحظهٔ اولین
پیام بررسی می‌شود** (و ۶ ساعت کش می‌شود). اسکن کامل اعضا پیش‌فرض خاموش است.

معاف: مالک ربات، مالک گروه، ادمین‌های ثبت‌شده، ادمین/سازندهٔ واقعی گروه و VIP.

- دستورها: `فیلتر لینک بیو` ، `لغو فیلتر لینک بیو` ، `وضعیت لینک بیو` ،
  `بررسی بیو` ، `لیست لینک بیو` ، `پاک لیست لینک بیو` ،
  `فیلتر آیدی بیو` / `لغو فیلتر آیدی بیو`
- مستندات و محدودیت‌ها: [`docs/BIO_LINK_FILTER.md`](docs/BIO_LINK_FILTER.md)
