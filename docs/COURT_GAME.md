# ⚖️ دادگاه روباه

بازی گروهی ۵ نفره با قاضی **هوش مصنوعی**: یک پروندهٔ نمایشی تشکیل می‌شود،
شاکی جرم را انتخاب می‌کند، متهم دفاع می‌کند، دو شاهد شهادت می‌دهند و وکیل
دفاعیهٔ نهایی را می‌نویسد؛ سپس قاضی هوش مصنوعی رأی می‌دهد و برندهٔ پرونده
جایزهٔ سکه می‌گیرد (در صورت محکومیت، پیام‌های متهم ۶۰ ثانیه پاک می‌شوند).

> ⚠️ این یک بازی نمایشی است؛ نتیجه‌اش سند اثبات جرم واقعی هیچ شخصی نیست.

---

## ۱. دستورها

| دستور | کار |
|---|---|
| `دادگاه` یا `دادگاه روباه` | ساخت پروندهٔ جدید و باز کردن ۶۰ ثانیه ثبت‌نام |
| `شرکت` | ثبت‌نام در پرونده (دقیقاً ۵ نفر، به‌ترتیب ورود) |
| نام جرم (`دزدی`، `قتل`، `توهین`، `دعوا و درگیری`، `کلاهبرداری`) | انتخاب موضوع شکایت توسط شاکی |
| متن آزاد | شرح شکایت، دفاع متهم، دو شهادت و دفاعیهٔ وکیل |

**قاعدهٔ ثبت‌نام:** هر عضو با هر بار نوشتن `شرکت` یک‌بار ثبت‌نام می‌شود؛
شمارنده فقط بالا می‌رود (۱ ← ۲ ← ۳ ← ۴ ← ۵) و هیچ‌وقت ریست نمی‌شود. پیام
دعوت ثبت‌نام هم فقط **یک بار** فرستاده می‌شود؛ بعد از هر ثبت‌نام تنها
پیام «✅ ثبت‌نام شما در پرونده انجام شد (n از ۵)» می‌آید. ثبت‌نام هر گروه
روی دیسک (`data/court_game/sessions/`) آینه می‌شود، پس اگر ربات وسط آن
۶۰ ثانیه ری‌استارت شود، `شرکت` بعدی همان پرونده را با همان فهرست ادامه
می‌دهد (پیام «⚖️ پروندهٔ این گروه باز است و ثبت‌نام آن ادامه دارد»).

بازی در «لیست بازی» با موضوع **«پرونده شکایت رو حل کن و برنده شو»** آمده و
زیر گارد `سرگرمی خاموش` / `سرگرمی فعال` قرار دارد (مثل بقیهٔ بازی‌های روباه).

## ۲. جریان بازی

```
دادگاه → ثبت‌نام ۶۰ ثانیه (۵ نفر)
        → تخصیص تصادفی نقش‌ها (بدون تکرار)
        → انتخاب جرم (شاکی)
        → شرح شکایت (شاکی)
        → دفاع (متهم)
        → شهادت (شاهد شاکی)
        → شهادت (شاهد متهم)
        → دفاعیهٔ نهایی (وکیل)
        → داوری هوش مصنوعی → رأی → جایزه → مجازات
```

نقش‌ها: **شاکی، متهم، شاهد شاکی، شاهد متهم، وکیل** (قاضی خودِ ربات است).

قواعد سخت:

* هر نقش **یک بار** روی یک نفر می‌نشیند و هیچ‌کس دو نقش ندارد.
* در هر مرحله فقط بازیکن همان نقش می‌تواند پیام بدهد؛ پیام دیگران مرحله را
  جلو نمی‌برد.
* هر مرحله فقط یک بار ثبت می‌شود؛ پیام تکراری پرونده را عوض نمی‌کند.
* دستورهای خود ربات (`لیست بازی`، `/...`، بازی‌های دیگر) در طول دادگاه
  بلعیده نمی‌شوند.
* اگر مهلت یک مرحله (پیش‌فرض ۱۲۰ ثانیه) تمام شود یا تعداد بازیکنان به ۵
  نرسد، پرونده **بدون جایزه** لغو و آرشیو می‌شود.

## ۳. سیستم اقتصادی (بدون کیف پول جدید)

همان بانک فعلی ربات استفاده می‌شود؛ جدول واحد `economy/rewards.py`:

| رأی | جایزه | گیرنده |
|---|---|---|
| تبرئهٔ متهم (`court_acquittal`) | ۱۳ سکه برنز | متهم |
| محکومیت متهم (`court_conviction`) | ۲۰ سکه برنز | شاکی |

* پرداخت با **شناسهٔ عددی واقعی** بازیکن انجام می‌شود، نه یوزرنیم.
* `reference = court:<case_id>:<winner_user_id>` یکتاست؛ دفتر تراکنش‌ها
  تراکنش تکراری با همان reference را ثبت نمی‌کند، پس ری‌استارت ربات یا
  اجرای دوبارهٔ داوری هرگز جایزه را دو بار پرداخت نمی‌کند.
* پرداخت فقط پس از **اعتبارسنجی کامل** خروجی هوش مصنوعی انجام می‌شود.

## ۴. سیستم مجازات (بدون سیستم موازی)

در صورت محکومیت:

1. پیام «⚖️ حکم دادگاه اجرا شد.» ارسال می‌شود.
2. یک پنجرهٔ ۶۰ ثانیه‌ای با کلید `(گروه، متهم)` باز می‌شود
   (`modules/court_game/punishment.py`).
3. در همان نقطهٔ ورودی پیام‌های گروه
   (`handlers/message_handler.handle_new_message`) هر پیام متهم داخل پنجره
   به **صف حذف موجود ربات** (`bot.message_delete_queue`) سپرده می‌شود.
4. پس از ۶۰ ثانیه پنجره بسته می‌شود، حذف متوقف می‌شود و گزارش کوتاه
   «⚖️ پایان اجرای حکم.» با تعداد پیام‌های پاک‌شده ارسال می‌گردد.

* فقط پیام‌های همان متهم در همان گروه حذف می‌شوند؛ پیام دیگران و بازی‌های
  دیگر گروه دست‌نخورده می‌مانند.
* اگر صف حذف نتواند پیامی را پاک کند (نبود دسترسی ربات، خطای entity…)
  در گزارش نهایی صریحاً «پاک نشد» اعلام می‌شود — وضعیت موفق به‌اشتباه
  اعلام نمی‌شود.

## ۵. تنظیمات هوش مصنوعی

سرویس: **Cloudflare Workers AI** (نقطهٔ پایانی سازگار با OpenAI):

```
POST https://api.cloudflare.com/client/v4/accounts/<AI_ACCOUNT_ID>/ai/v1/chat/completions
Authorization: Bearer <AI_API_KEY>       # توکن کاربری با پیشوند cfut_
```

مدل پیش‌فرض: `@cf/meta/llama-3.3-70b-instruct-fp8-fast` — سریع‌ترین مدل متنی
باکیفیت فارسی در فهرست واقعی مدل‌های این حساب (پاسخ رأی ≈ ۲ ثانیه، آزمون
واقعی همین مخزن). با `AI_MODEL` قابل تغییر است.

متغیرهای محیطی (در `.env`؛ این فایل در `.gitignore` است و هرگز commit
نمی‌شود — هیچ کلیدی داخل کد Python نوشته نشده است):

```env
AI_API_KEY=cfut_…
AI_ACCOUNT_ID=…
AI_MODEL=@cf/meta/llama-3.3-70b-instruct-fp8-fast
AI_BASE_URL=            # اختیاری؛ اگر پر شود اولویت دارد
AI_TIMEOUT_SECONDS=75
AI_RETRIES=1
```

### خروجی قاضی

مدل فقط این JSON را می‌دهد:

```json
{"case_id":"…","verdict":"plaintiff|defendant",
 "reason_1":"…","reason_2":"…","reason_3":"…","confidence":0.0}
```

ربات سپس خروجی نهایی معتبر را با **شناسه‌های واقعی پرونده** می‌سازد:

```
case_id, verdict, winner_user_id, winner_username,
defendant_user_id, defendant_username,
reason_1, reason_2, reason_3, confidence
```

* `verdict` نامعتبر، دلیل ناقص یا `confidence` نامعتبر ⇒ **پرداخت و مجازات
  انجام نمی‌شود**، پیام خطای مدیریت‌شده ارسال و پرونده با وضعیت
  `judge_error` آرشیو می‌شود.
* اگر شواهد کافی نباشد، مدل طبق اصل بی‌گناهی رأی به نفع متهم می‌دهد.

### امنیت در برابر تزریق دستور

* system prompt ثابت و جداست؛ متن کاربران فقط داخل `<CASE_DATA>` به‌عنوان
  «داده» می‌رود.
* تگ‌های `<CASE_DATA>`/`</CASE_DATA>` از متن کاربر پاک می‌شوند و طول متن‌ها
  محدود است؛ هیچ پیام کاربری به‌عنوان دستور سیستمی ارسال نمی‌شود.
* تحلیل هر پیام در پس‌زمینه انجام و در `ai_logs/` ذخیره می‌شود و **هیچ**
  پاسخ زودهنگامی به گروه داده نمی‌شود؛ تنها تأیید کوتاه
  «پیام شما با موفقیت در پرونده ثبت شد. ⚖️» ارسال می‌گردد.

## ۶. ذخیره‌سازی دائمی داخل پروژه

مسیرها از محل واقعی فایل ماژول ساخته می‌شوند
(`Path(__file__).resolve().parents[2]`)، پس اجرای ربات از هر دایرکتوری
همان مسیر را می‌دهد و هیچ‌چیز در `$HOME`، `/tmp` یا حافظهٔ عمومی Termux
نوشته نمی‌شود:

```
<project>/data/court_game/
├── cases/      یک فایل JSON برای هر پرونده (شناسهٔ یکتا)
├── sessions/   وضعیت بازی‌های فعال + پنجره‌های مجازات (برای بازیابی)
├── ai_logs/    گزارش تحلیل‌های هوش مصنوعی (JSONL به‌ازای پرونده)
├── results/    آرشیو نتیجهٔ نهایی/لغو/خطای هر پرونده
└── config/     settings.json (تنظیمات اختصاصی بازی)
```

* نوشتن اتمیک (`modules/atomic_write`: فایل موقت + `os.replace` + fsync).
* هر پرونده فایل مستقل دارد؛ چند دادگاه هم‌زمان در گروه‌های مختلف هرگز
  روی یک فایل نمی‌نویسند.
* پس از ری‌استارت، `storage.recover()` پرونده‌های نیمه‌کاره را
  `interrupted` علامت می‌زند، آرشیو می‌کند و **بدون جایزه** می‌بندد.
* تنظیمات (`data/court_game/config/settings.json`):
  `join_seconds=60`، `step_seconds=120`، `punishment_seconds=60`،
  `ai_timeout_seconds=75`، `ai_retries=1`.
* برای مسیر دلخواه (مثلاً استقرار جدا) فقط `COURT_GAME_DATA_DIR` را تنظیم
  کنید؛ پیش‌فرض هیچ‌وقت از پروژه بیرون نمی‌رود.

## ۷. ساختار کد

```
modules/court_game/
├── texts.py       همهٔ متن‌های فارسی + قالب Bold (بدون نقل‌قول)
├── storage.py     مسیرها، نوشتن اتمیک، شناسهٔ یکتا، بازیابی
├── game.py        state، نقش‌ها، مراحل، پرونده، حلقهٔ بازی
├── ai_judge.py    قاضی هوش مصنوعی + اعتبارسنجی سخت‌گیرانه
└── punishment.py  پنجرهٔ ۶۰ ثانیه‌ای حذف پیام با صف حذف موجود
handlers/court_game_router.py   اتصال به ربات (نازک، بدون state)
```

اتصال به ربات فقط از `handlers/fox_games_router.py` است (همان روتر همهٔ
بازی‌های روباه)؛ هیچ مسیر موازی و هیچ state دومی ساخته نشده است.

## ۸. قالب پیام‌ها

* همهٔ پیام‌ها فارسی، رسمی و **کاملاً Bold** هستند. **هیچ پیامی نقل‌قول
  (Blockquote) نمی‌شود** — نقل‌قول در این بازی خواسته نشده و حذف شده است.
* همه‌چیز **ردیفی** است: بین خطوط هیچ خط خالی نیست.
* تنها استثنا پیام آغاز دادگاه است که پیش از فهرست شماره‌دار بازیکنان
  **یک** خط خالی دارد:

```
⚖️ پرونده ساخته شد و دادگاه رسمی آغاز گردید

1 - قاضی: @foxora_bot
2 - شاکی: @player101
3 - متهم: بازیکن104
4 - شاهد شاکی: @player103
5 - شاهد متهم: @player105
6 - وکیل: بازیکن102
```

* نام کاربر: یوزرنیم اگر دارد (`@name`)، وگرنه نام نمایشی
  (سیاست مشترک `modules.user_display.format_user`). شناسهٔ عددی هرگز نمایش
  داده نمی‌شود.
