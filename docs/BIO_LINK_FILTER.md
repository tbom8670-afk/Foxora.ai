# 🖇 قابلیت «تشخیص لینک در بیوگرافی کاربران» — Foxora / Foxora2

این سند می‌گوید قابلیت چطور کار می‌کند، چه چیزی **واقعاً** از API سروش
گرفتنی است، چه محدودیتی دارد، و چطور فعال/غیرفعال می‌شود.

---

## ۱) تأیید توانایی کتابخانه (بدون حدس)

کتابخانهٔ نصب‌شده همان `splusthon` است (فورک Telethon برای سروش پلاس) و
مسیر خواندن بیوگرافی را **دارد**:

| مورد | وضعیت تأیید |
|---|---|
| `splusthon.tl.functions.users.GetFullUserRequest` | ✅ موجود — سازندهٔ TL `0xb60f5918` (همان `users.getFullUser`) |
| پارامتر ورودی | `GetFullUserRequest(id: InputUser)` |
| پاسخ | `splusthon.tl.types.users.UserFull(full_user, chats, users)` |
| فیلد بیوگرافی | ✅ `full_user.about` (نوع `str`، اختیاری) |
| ساختن ورودی سبک | ✅ `splusthon.utils.get_input_user(user)` — بدون RPC اضافه وقتی آبجکت `User` با `access_hash` در دست است |
| فهرست اعضا | ✅ `client.iter_participants(entity, limit=...)` → `channels.getParticipants` (با صفحه‌بندی و سقف) |
| محدودیت | `users.getFullUser` برای کاربران دیگر به تنظیمات حریم خصوصی سروش وابسته است؛ بیوی خالی یا نبود دسترسی، **تخلف حساب نمی‌شود** |

نتیجه: نیازی به تعویض کتابخانه یا تغییر روش ورود/نشست **نبود** و انجام هم نشد.

قید مهم و صادقانه: هیچ‌کدام از این فراخوانی‌ها در این محیط (بدون نشست واقعی)
به شبکه زده نشده‌اند؛ صحت **مسیر فراخوانی و ساختار داده** روی خودِ کتابخانه
تأیید شده و رفتار خطاها/خالی‌بودن/FloodWait با کلاینت جعلی تست شده است.
اجرای زنده با نشست خود شما انجام می‌شود.

## ۳) روش فعال‌سازی و دستورها

قابلیت برای گروه‌های فعالِ ربات **به‌صورت پیش‌فرض روشن** است (برای اینکه
برخلاف خواستهٔ «واقعاً اجرا شود» خاموش نماند). برای تغییر رفتار پیش‌فرض:

```env
BIO_LINK_DEFAULT_ENABLED=0   # پیش‌فرض گروه‌های بدون تنظیم را خاموش می‌کند
```

دستورها (فقط مالک ربات، مالک گروه یا ادمینِ ثبت‌شده؛ هر سه شکل بدون پیشوند،
`!` و `/` پذیرفته می‌شود):

| دستور | کار |
|---|---|
| `فیلتر لینک بیو` | روشن کردن برای همین گروه |
| `لغو فیلتر لینک بیو` | خاموش کردن برای همین گروه |
| `وضعیت لینک بیو` | تعداد بررسی‌شده/دارای لینک، زمان آخرین اسکن |
| `بررسی بیو` | اسکن فوری اعضا در پس‌زمینه |
| `لیست لینک بیو` | فهرست کاربران دارای لینک (تا ۳۰ مورد) |
| `پاک لیست لینک بیو` | پاک کردن نتیجه‌ها برای بررسی مجدد |
| `فیلتر آیدی بیو` / `لغو فیلتر آیدی بیو` | آیا `@username` تنها هم «لینک» حساب شود (پیش‌فرض: خیر) |

## ۴) رفتار دقیق

### تشخیص
`http/https/ftp/hxxp`، `www.`، دامنهٔ برهنه با TLD رایج، `t.me` /
`telegram.me` / `joinchat` / `t.me/+HASH`، `sapp.ir` / `splus.ir` /
`soroush.ir` / `soroush.plus`، لینک IP.
مقاوم به: فاصله/نیم‌فاصله/کاراکتر بی‌عرض داخل لینک، نقطه‌های غیر ASCII
(`۔ 。 ․ · •`)، اسلش و دونقطهٔ تمام‌عرض، `[.]` و `(dot)` و ` dot `، حروف
ریاضی/تمام‌عرض، `s i t e . c o m`، ارقام فارسی.
**لینک ناقص** (`http://`، `t.me/`، `www.`) و متن عادی و آیدی بدون زمینه
(`@ali`) لینک حساب نمی‌شوند.

### مجازات — بدون سیستم موازی
کاربر دارای لینک بیو در همان مسیر استاندارد `is_spam` ربات قرار می‌گیرد؛
یعنی **همان** شمارندهٔ `tracker`، **همان** `warning_threshold` گروه،
**همان** `send_warning`، **همان** صف حذف، و **همان**
`admin_actions.punish_user` که طبق `punishment_mode` گروه سکوت یا اخراج
می‌کند. هیچ شمارنده/سابقهٔ دومی ساخته نمی‌شود؛ `user_history` و
`admin_tools.log_action` هم مثل بقیهٔ فیلترها کار می‌کنند.
مجازات تکراری برای همان کاربر در همان بازه اجرا نمی‌شود (`punished_users`).
VIP، ادمین/مالک ثبت‌شده و گروه خاموش معاف‌اند.

### دامنهٔ بررسی: فقط کاربرانی که پیام می‌دهند (سیاست پیش‌فرض)
- هر کاربری که در گروه **پیام** می‌دهد، همان لحظه بیوگرافی‌اش خوانده می‌شود
  (`BIO_LINK_AWAIT_FIRST_CHECK=1`، سقف انتظار `BIO_LINK_AWAIT_TIMEOUT=8s`).
  یعنی **اولین پیام** همان کاربر هم بررسی و طبق سیستم موجود مدیریت می‌شود.
- نتیجه ذخیره می‌شود؛ پیام‌های بعدی همان کاربر تا `BIO_LINK_TTL_SECONDS`
  **هیچ RPC جدیدی** نمی‌سازند.
- اسکن کامل «همهٔ اعضا» به‌صورت پیش‌فرض **خاموش** است
  (`BIO_LINK_AUTO_SCAN_MEMBERS=0`) و فقط با دستور `بررسی بیو` یا روشن کردن
  همان متغیر انجام می‌شود.
- اگر سرویس کند یا خطا بدهد، پیام بلاک نمی‌شود؛ بررسی به پس‌زمینه می‌رود و
  همان پیام بدون تخلف پردازش می‌شود.

### اسکن اختیاری اعضا (بدون فشار به سرور)
- فقط با `BIO_LINK_AUTO_SCAN_MEMBERS=1` یا دستور `بررسی بیو`.
- شروع: ۱۲۰ ثانیه بعد از بالا آمدن ربات (`BIO_LINK_START_DELAY`).
- هر گروه: حداکثر `BIO_LINK_SCAN_LIMIT` (پیش‌فرض ۲۰۰) نفر در هر دور،
  بودجهٔ زمانی `BIO_LINK_SCAN_BUDGET` (۱۲۰ ثانیه)، فاصلهٔ
  `BIO_LINK_RPC_DELAY` (۰٫۴ ثانیه) بین هر درخواست.
- هر کاربر فقط هر `BIO_LINK_TTL_SECONDS` (۶ ساعت) دوباره بررسی می‌شود؛
  اسکن دوباره داخل TTL هیچ RPC جدیدی نمی‌زند.
- ادمین‌ها، ربات‌ها و خودِ حساب سشن در اسکن رد می‌شوند.
- ورود عضو جدید: یک بررسی در پس‌زمینه.
- پیام کاربر ناشناخته: بررسی در صف پس‌زمینه (هم‌زمانی ۱)، هرگز در مسیر پیام RPC نمی‌شود.
- FloodWait: اسکن آن گروه متوقف و ۵ دقیقه بعد ادامه می‌یابد.

### ذخیره‌سازی
`~/.foxora2/config/bio_link.json` (اتمیک، با debounce). برای هر کاربر فقط
`link`، `label`، `status`، `bio_len`، `name`، `checked_at` ذخیره می‌شود —
**متن بیوگرافی هرگز ذخیره نمی‌شود**. سقف ۸۰۰۰ کاربر در هر گروه با حذف
قدیمی‌ترین‌ها.

### لاگ و امنیت
فقط شناسهٔ عددی، `status` و برچسب نوع لینک لاگ می‌شود. هیچ متن بیو، شماره،
توکن یا رشتهٔ نشست چاپ نمی‌شود. خطای API هرگز باعث مجازات نمی‌شود.

## ۵) پیکربندی اختیاری

```env
BIO_LINK_DEFAULT_ENABLED=1        # روشن/خاموش پیش‌فرض گروه‌ها
BIO_LINK_DETECT_USERNAME=0        # @username تنها هم لینک حساب شود؟
BIO_LINK_TTL_SECONDS=21600        # ۶ ساعت
BIO_LINK_SCAN_LIMIT=200           # سقف اعضا در هر دور
BIO_LINK_SCAN_INTERVAL=21600      # فاصلهٔ دورهای اسکن
BIO_LINK_SCAN_BUDGET=120          # بودجهٔ زمانی هر اسکن (ثانیه)
BIO_LINK_RPC_DELAY=0.4            # فاصلهٔ بین درخواست‌ها
BIO_LINK_FETCH_TIMEOUT=20         # تایم‌اوت هر درخواست
BIO_LINK_START_DELAY=120          # تأخیر اسکن اولیه
BIO_LINK_AWAIT_FIRST_CHECK=1      # اولین پیام هر کاربر منتظر بررسی بیو بماند
BIO_LINK_AWAIT_TIMEOUT=8          # سقف انتظار همان بررسی (ثانیه)
BIO_LINK_AUTO_SCAN_MEMBERS=0      # اسکن دوره‌ای «همهٔ اعضا» (پیش‌فرض خاموش)
BIO_LINK_CHECK_ON_MESSAGE=1       # بررسی بیو کاربر پیام‌دهنده
BIO_LINK_CHECK_ON_JOIN=1          # بررسی بیوی عضو جدید
BIO_LINK_MAX_PENDING=400          # سقف صف بررسی پس‌زمینه
```

## ۶) محدودیت‌های واقعی

1. اگر سروش بیوی کاربر را به این حساب نشان ندهد (`no_access`) یا بیو خالی
   باشد، تشخیص ممکن نیست و کاربر مجازات نمی‌شود. این «شبیه‌سازی» نشده است.
2. `getParticipants` برای گروه‌های بسیار بزرگ سقف دارد؛ به همین دلیل اسکن
   تدریجی و TTL-محور است، نه یک‌باره برای همه.
3. دامنهٔ یونیکد (مثل `سایت.com`) تشخیص داده نمی‌شود؛ فقط دامنهٔ لاتین.
4. لینک‌های ناقص عمداً نادیده گرفته می‌شوند تا متن عادی مجازات نشود.
5. چون بررسی «هنگام پیام» است، کاربری که هیچ‌وقت پیام نمی‌دهد بررسی نمی‌شود
   (این خواستهٔ صریح سیاست پیش‌فرض است). برای پوشش کامل، `BIO_LINK_AUTO_SCAN_MEMBERS=1`.
