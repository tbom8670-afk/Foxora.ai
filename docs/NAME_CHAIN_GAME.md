# ⛄️ بازی «اسم‌چین»

رقابتِ زنجیره‌ایِ اسم با ربات: ربات یک حرف می‌دهد، کاربر یک اسمِ ایرانی با آن
حرف می‌گوید، ربات با **حرفِ آخرِ** همان اسم جواب می‌دهد و این‌طور ادامه
پیدا می‌کند تا یکی گیر کند.

دستورِ شروع: **اسم چین** (همچنین «اسم‌چین»، «اسمچین»، «بازی اسم چین»).

## ۱) متنِ شروع (عیناً)

```
⛄️بازی اسم چین

دقت کن دوست، هرجا که بلد نبودی اسمی بگی بگو «نمیدونم» تا بازنده بشی، یا برای تموم کردن بازی هم بگو «نمیدونم».

برای جواب گرفتن باید هر پیام رو روی ربات ریپلای کنی.

حالا برای شروع یک اسم با «ل» بگو
```

حرفِ آخر، تصادفی و از میانِ حروفی انتخاب می‌شود که در استخرِ نام‌ها
دست‌کم سه نام دارند (بازی همیشه قابلِ شروع باشد).

## ۲) قاعده‌ها

| قاعده | جزئیات |
| --- | --- |
| فقط ریپلای | تنها پیام‌هایی پردازش می‌شوند که روی **هر پیامِ خودِ ربات** ریپلای شده باشند (لازم نیست حتماً آخرین پیام باشد)؛ پیامِ آزادِ گروه و ریپلای روی پیامِ کاربران هیچ‌وقت بلعیده نمی‌شود |
| نامِ واقعی | نام باید در `names.txt` یا دیتابیسِ ۲۴هزارتاییِ `modules.persian_names` باشد |
| حرفِ درست | نام باید با حرفی که ربات خواسته شروع شود (آ = ا) |
| بدونِ تکرار | هیچ نامی — نه از کاربر، نه از ربات — دوبار در همان بازی استفاده نمی‌شود |
| زنجیره | ربات با **حرفِ آخر** اسمِ کاربر جواب می‌دهد؛ حرفِ بعدیِ کاربر، حرفِ آخرِ اسمِ ربات است |
| باختِ کاربر | «نمی‌دونم» (هر املایی) ⇒ بازی تمام و پیامِ «بازنده شدی ⛄️» |
| باختِ ربات | ربات برای حرفِ مورد نظر نامی نداشته باشد ⇒ «نمی‌دونم» + «🏆 تو بردی!» |
| جداییِ چت‌ها | وضعیت با کلیدِ گروه (`normalize_group_id`) نگه‌داری می‌شود؛ بازیِ دو گروه قاطی نمی‌شود |

هنگامِ ردشدن، ربات **دلیل** را می‌گوید تا کاربر دوباره تلاش کند:

* «❌ «سارا» با «ل» شروع نمی‌شه …» (حرفِ اشتباه)
* «🔁 «لاله» قبلاً توی همین بازی استفاده شده …» (تکراری)
* «🤔 «لززززز» رو به‌عنوان اسم ایرانی نمی‌شناسم …» (اسمِ الکی)
* «✍️ فقط اسم بفرست — یک یا دو کلمه …» (جمله)

## ۲٫۵) چرا بازی «بعد از حرفِ اول» می‌خوابید و چه چیزی درست شد

باگِ گزارش‌شده با عکس: ربات حرفِ اول را می‌گفت، کاربر جواب می‌داد، ربات هم
جواب می‌داد — ولی از آن به بعد هیچ واکنشی نبود.

ریشه: ادامهٔ بازی به «شناسهٔ پیامِ ربات» گره خورده بود و آن شناسه از
``event.reply(...)`` خوانده می‌شد. کلاینت در بعضی مسیرها ``None``/``Updates``
برمی‌گرداند؛ شناسه ثبت نمی‌شد و **هر ریپلایِ بعدی «ریپلای روی پیامِ دیگر»
تلقی و بی‌صدا نادیده گرفته می‌شد.**

سه تغییر که این را برای همیشه می‌بندد:

1. **شناسه از هر شکلی استخراج می‌شود** — ``Message``, ``Updates``, لیست یا
   عدد، با همان منطقِ آزمودهٔ ``notice_cleanup.extract_sent_id``
   (``game.extract_message_id``).
2. **ملاکِ پذیرش، «ریپلای روی ربات» است نه «ریپلای روی آخرین پیام»** — اگر
   ``reply_to.from_id`` برابرِ ``bot_account_id`` باشد نوبت پذیرفته می‌شود؛
   حتی وقتی شناسهٔ ثبت‌شده نامعلوم یا قدیمی است. اگر کلاینت ``from_id`` را هم
   ندهد، همان پیام از سرور خوانده می‌شود
   (``_name_chain_reply_sender``).
3. **ضدِ تحویلِ تکراری** — شناسهٔ پیامِ ورودی در وضعیت نگه داشته می‌شود؛ اگر
   کلاینت یک آپدیت را دوبار بدهد، نوبت دوبار جلو نمی‌رود و پیامِ تکراری
   فرستاده نمی‌شود.

برای عیب‌یابی در گروه، لاگِ ``NAME CHAIN IGNORE … reason=not_a_bot_reply``
دقیقاً می‌گوید چرا یک پیامِ درونِ بازی مصرف نشد.

## ۳) نرمال‌سازی

`modules/name_chain/game.py::normalize`:

* `ي`/`ك`/`ى` عربی → `ی`/`ک`
* `ة`/`ۀ` → `ه`، `أ`/`إ`/`آ` → `ا`، `ؤ` → `و`، `ئ` → `ی`
* حذفِ اعراب (`\u064b`–`\u0652`, `\u0670`)، نیم‌فاصله و نویسه‌های نامرئی
* نشانه‌ها («»، !، ؟، …) → فاصله؛ فاصله‌های اضافه یکی می‌شوند
* «نمی‌دونم» پس از نرمال‌سازی و **حذفِ فاصله** مقایسه می‌شود، پس
  «نمیدونم»، «نمی‌دونم»، «نمی دونم»، «نمیدانم»، «نمی دانم» همه یکی‌اند.

## ۴) داده‌ها

* `modules/name_chain/names.txt` — ۴۴۲ نامِ ایرانی (دخترانه و پسرانه)، هر
  خط یک نام، خطوطِ `#` نادیده گرفته می‌شوند. هنگامِ import یک‌بار خوانده و
  در `NAMES` (set) و `NAMES_BY_LETTER` (dict بر اساسِ حرفِ اول) کش می‌شود.
* برای پذیرشِ نام‌های کاربر، علاوه بر این استخر از
  `modules.persian_names.is_known_name` (۲۴٬۶۶۳ نام) هم استفاده می‌شود؛ پس
  کاربرِ درست‌گو بابتِ نامی که در `names.txt` نیست جریمه نمی‌شود.
* ربات هنگامِ انتخابِ جواب، نام‌هایی را ترجیح می‌دهد که حرفِ آخرشان هم نام
  دارد؛ این‌طور بازی طبیعی ادامه پیدا می‌کند و ربات با بن‌بستِ یک‌طرفه
  برنده نمی‌شود.

## ۵) فایل‌های تغییرکرده

```

modules/name_chain/texts.py         همهٔ متن‌های فارسی/دوستانه
modules/name_chain/names.txt        استخرِ نام‌ها (۴۴۲ نام)
handlers/message_handler.py         شروعِ بازی، پردازشِ ریپلای، مسدودسازیِ مسیرِ جستجو
handlers/message_handler.py         لیستِ بازی: ردیفِ «🫆اسم چین» + Bold
modules/entertainment_control.py    «اسم چین» در GAME_COMMANDS (سرگرمی خاموش)
modules/group_dispatch.py           «اسم چین» در دستورهای عمومی

```

## ۶) لیستِ بازی

در خروجیِ «لیست بازی»، بلافاصله بعد از «📝 اسم فامیل»:

```
🫆اسم چین
رقابت با ربات با آخر اسم یک اسم بگید
```

و «🫆اسم چین» با `MessageEntityBold` (آفست بر حسبِ UTF-16) Bold می‌شود.

## ۷) تست

```bash
PYTHONPATH=. python3 tests/test_name_chain.py      # 126 پاس
```

پوشش: نرمال‌سازی و همهٔ املای «نمی‌دونم»، بارگذاریِ `names.txt`، متنِ دقیقِ
شروع، تصادفی و بازی‌پذیر بودنِ حرف، فقط‌ریپلای، چهار دلیلِ ردشدن، زنجیرهٔ
حرفِ آخر و بی‌تکرار بودنِ نام‌ها، باختِ کاربر، باختِ ربات، جداییِ چت‌ها،
اتصال به لیستِ بازی/سرگرمی/dispatch، یک اجرای واقعی از مسیرِ
`handle_new_message` (شروع ← پیامِ آزادِ نادیده ← ریپلای ← ریپلای روی پیامِ
قدیمی‌ترِ ربات ← ریپلای روی پیامِ کاربر (نادیده) ← «نمی‌دونم»)، شبیه‌سازیِ
کلاینتی که شناسهٔ پیام نمی‌دهد و ادامهٔ بازی تا نوبتِ سوم با آن، و در پایان
ضدِ تحویلِ تکراری و استخراجِ شناسه از Message/Updates/لیست/None.

## ۸) نکتهٔ استقرار

* بازی هیچ تغییری در `config.json` یا دیتابیس نمی‌دهد؛ همه‌چیز در حافظه است
  و با ری‌استارت، بازیِ نیمه‌کاره بسته می‌شود (بعد از ۳ ساعت بی‌خبری هم
  خودش پاک می‌شود تا حافظه بالا نرود).
* برای اضافه‌کردنِ نام، فقط یک خط به `names.txt` اضافه کنید؛ نیازی به
  تغییرِ کد نیست.
